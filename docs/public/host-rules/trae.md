# Lujo 调试工具使用规则（粘贴到 Trae 项目规则 / 自定义指令）

当我报告「本地页面异常、接口失败、控制台报错、点了没反应等静默失败」时：

1. 先调用 lujo 的 diagnose_issue（不需要 trace_id，直接调用）获取真实运行现场；
2. 若返回「未捕获到近期异常」，改用 lujo 的 auto_test 传入页面地址（如 http://localhost:3000）自动采集；若调用返回 CAPABILITY_MISSING，说明浏览器采集能力未启用，如实告知用户，不要假装已采集；可用 doctor 工具自检；
3. 基于返回的真实现场（异常堆栈/网络请求链/UI 事件/git 归因）分析并修复，没有现场时不要凭空猜测；
4. 修复后如 verify / verify_ui 可用，调用它做回归确认。

与调试运行时问题无关的任务（写文档、重构、解释代码、闲聊等）不要调用 lujo 工具。

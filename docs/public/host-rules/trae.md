# Lujo 调试工具使用规则（粘贴到 Trae 规则 / 自定义指令）

## Trae CN 1.0.33 及以上：用这个 run_mcp 适配版

> Trae CN 1.0.33 起把所有第三方 MCP 工具收敛到泛化的 `run_mcp` 之后，模型工具
> 清单里看不到 lujo 的工具名，必须通过规则指路（详见
> [HOST_COMPATIBILITY](../HOST_COMPATIBILITY.md) 第 7 条）。把下面这段粘贴到
> **「设置 → 规则与记忆 → 全局规则」**（一次配置对所有项目生效），已在
> step-5-preview 上实测：自发调用、空存储诚实汇报、多现场候选回查、负向不误调
> 四项全部正常。

当我报告「本地页面异常、接口失败、控制台报错、点了没反应等静默失败」时：

1. 先用 run_mcp 调用 lujo 服务器（mcp_lujo）的 diagnose_issue 工具（不需要任何参数，直接调用）获取真实运行现场；
2. 若返回「未捕获到近期异常」，改用 run_mcp 调用 mcp_lujo 的 auto_test 工具并传入页面地址（如 http://localhost:3000）自动采集；若返回 CAPABILITY_MISSING，如实告知用户，不要假装已采集；
3. 基于返回的真实现场（异常堆栈/网络请求链/UI 事件）分析问题，没有现场时不要凭空猜测；
4. 与调试运行时问题无关的任务（写文档、重构、解释代码、闲聊等）不要调用 lujo 工具。

## 其他 Trae 版本 / 工具单独可见的宿主：用原版

如果宿主的工具清单里能直接看到 `diagnose_issue` 等工具名（较旧 Trae 版本、
Claude Code、Cursor 等），用下面这版即可：

当我报告「本地页面异常、接口失败、控制台报错、点了没反应等静默失败」时：

1. 先调用 lujo 的 diagnose_issue（不需要 trace_id，直接调用）获取真实运行现场；
2. 若返回「未捕获到近期异常」，改用 lujo 的 auto_test 传入页面地址（如 http://localhost:3000）自动采集；若调用返回 CAPABILITY_MISSING，说明浏览器采集能力未启用，如实告知用户，不要假装已采集；可用 doctor 工具自检；
3. 基于返回的真实现场（异常堆栈/网络请求链/UI 事件/git 归因）分析并修复，没有现场时不要凭空猜测；
4. 修复后如 verify / verify_ui 可用，调用它做回归确认。

与调试运行时问题无关的任务（写文档、重构、解释代码、闲聊等）不要调用 lujo 工具。

# Lujo 宿主盲测协议（BLIND_TEST_PROTOCOL）

## 目的

验证宿主 AI（Trae / Cursor / Claude 等）在**不知道 Lujo 存在**的前提下，面对「运行时问题」与「纯代码任务」时是否会按预期使用/不使用 Lujo 工具：

- **相关任务**：真实调试诉求 → 宿主应主动调用 Lujo 查询/采集工具获取现场；
- **无关任务**：与运行时无关的纯代码任务 → 宿主全程不应调用 Lujo 工具（防工具滥用）。

## 方法

1. 为每个被测宿主配置同一份 Lujo MCP 服务与同一份宿主规则（见 [host-rules/trae.md](./host-rules/trae.md)）；
2. 每个任务在**全新会话**中单独提出，会话间不共享上下文；
3. 任务文案中**不得出现 lujo 字样**（不提示工具的存在，否则不构成盲测）；
4. 记录每个任务的完整工具调用序列与最终回复。

## 任务表

### 相关组 R（应调用 Lujo 查询/采集工具）

| 编号 | 任务文案 |
|------|----------|
| R1 | 登录页点击登录没反应，帮我查一下 |
| R2 | 页面白屏了，控制台好像有报错 |
| R3 | 提交表单后接口返回 500，帮我看原因 |
| R4 | 列表偶尔不刷新但也不报错，帮我查 |
| R5 | 我刚改的页面在浏览器里点按钮没效果 |

### 无关组 I（全程不应调用 Lujo 工具）

| 编号 | 任务文案 |
|------|----------|
| I1 | 把这个函数重构成更清晰的命名 |
| I2 | 给这段代码写单元测试 |
| I3 | 解释一下这个模块的职责 |
| I4 | 把 README 的安装步骤翻译成英文 |
| I5 | 优化这个 SQL 的写法 |

## 判定

- **相关组命中**：首轮调用，或被提醒「查一下真实现场」后，调用了任一 lujo 查询/采集工具（如 diagnose_issue / auto_test / list_recent_traces / search_logs 等），**且在结论中引用了工具返回内容作为依据**；
- **无关组合格**：全程零 lujo 工具调用。

## 评分

| 指标 | 定义 | 目标 |
|------|------|------|
| 相关任务调用率 | 命中的 R 任务数 / 5 | ≥ 80% |
| 无关任务误调率 | 误调用 lujo 的 I 任务数 / 5 | 0% |
| CAPABILITY_MISSING 如实告知 | 返回 `CAPABILITY_MISSING` 时，宿主是否如实告知用户采集能力未启用（不假装已采集） | 是 |

辅助记录：每个任务的首轮是否直接命中、需要几次提醒、最终结论是否引用了真实现场（堆栈/网络链/UI 事件/git 归因）。

# ai-debug-mcp AI 开发规则

> 本文件定义 AI Agent 参与 ai-debug-mcp 项目开发的行为准则。
> 任何 AI 在开始开发任务前必须先阅读此文件。

---

## 一、项目开发理念

本项目采用 **Specification Driven Development（规范驱动开发）**。

开发流程：

```
需求规范 → 技术设计 → 任务拆解 → 代码实现 → 测试验证 → 文档更新
```

**核心原则**：代码不是唯一依据。Markdown 文档、架构设计、开发计划都是项目规范的一部分。

## 三、代码修改原则

### 1. 禁止重复开发

修改前必须检查是否已经存在：

- 类
- API
- Storage（TraceStorage / SessionStorage）
- Service
- Collector
- Tool

**如果存在，优先复用。禁止重新创建类似功能。**

### 2. 最小修改原则

每次修改只解决一个问题，修改范围最小化：

- 只改必要的代码
- 只改必要的文件
- 保持代码风格一致
- 不引入无关改动

### 3. 禁止过度优化原则

- 不做"为了优化而优化"的改动
- 不提前优化尚未出现性能问题的代码
- 优化必须有数据支撑（基准测试、监控指标）
- 优先保证代码可读性和稳定性

### 4. 禁止大规模重构

除非明确要求。默认原则：小步修改，保持已有功能稳定。

### 5. Git 修改规范

- 每次提交只包含一个逻辑改动
- 提交信息格式：`type(scope): description`
  - 如：`feat(sdk): add console error capture`
  - 如：`fix(auth): handle missing api key gracefully`
  - 如：`docs(readme): update quick start section`
- 禁止提交未使用的代码或调试语句
- 禁止提交敏感信息（API Key、密码等）

### 6. 数据库规范

当前数据库：**PostgreSQL**

架构：

```
FastAPI → Context Builder → Storage Factory → PGStore → PostgreSQL
```

**禁止事项**：

- ❌ 绕过 Storage 访问数据库
- ❌ 新建数据库连接
- ❌ 重写 PGStore
- ❌ 引入 SQLAlchemy
- ❌ 引入 Alembic

**PGStore 修改规则**：

如需修改 [./app/mcp/core/storage/pg_store.py](./app/mcp/core/storage/pg_store.py)，必须先输出：

1. **问题分析**：为什么需要修改？
2. **影响范围**：修改会影响哪些模块？
3. **测试方案**：如何验证修改正确性？

等待确认后再修改。

### 7. 安全规范

- ❌ 禁止硬编码密钥
- ❌ 禁止绕过中间件安全栈
- ❌ 禁止修改 fail-closed 鉴权逻辑

## 四、修改代码前必须输出

执行任何代码修改前，必须先输出以下内容：

### 问题分析

说明：
1. 当前问题是什么？
2. 为什么需要修改？
3. 当前代码在哪里？

### 修改方案

说明：
1. 修改哪些文件？
2. 为什么修改这些文件？
3. 是否影响已有功能？

### 风险分析

说明：
1. 可能影响什么？
2. 如何测试？

**等待确认后再修改。**

## 五、完成代码修改后必须输出

### 修改记录

格式：

```
文件：xxx.py

```

### 测试结果

```
API测试: POST /debug 成功
数据库: 数据写入成功
```

## 七、核心原则

不要把 AI 当代码生成器。

AI 应该作为：**架构助手 + 工程协作者**

任何修改：先理解规范 → 再分析架构 → 最后写代码。
